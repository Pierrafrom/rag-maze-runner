A Retrieval-Augmented Generation (RAG) system that answers questions, in
French, about the Maze Runner universe. It reads its knowledge from the
French Maze Runner Fandom wiki and uses Google Gemini, LangChain, and the
Chroma vector database to find relevant passages and generate grounded
answers instead of relying on the LLM's own memory.

Originally built as a university group project (4 people, Spring 2026),
it goes well beyond a basic RAG demo: hybrid retrieval, a re-ranking step,
two layers of hallucination mitigation (CRAG and Self-RAG), a full
evaluation suite (RAGAS), a Streamlit chat UI, and a Dockerized deployment.

## What it does

- **Retrieval**: a Parent Document Retriever splits the wiki into small
  "child" chunks for accurate search, each linked to a larger "parent"
  chunk that gets returned for context. Multi-Query generates 3
  reformulations of the question, searches each in parallel, and merges
  the results with Reciprocal Rank Fusion (RRF).
- **Re-ranking**: FlashRank (a local, multilingual model) re-ranks the top
  15 fused results down to the top 4 most relevant.
- **Hallucination mitigation**: CRAG grades the retrieved context as
  relevant, ambiguous, or off-topic before generation even happens (an
  off-topic verdict skips the LLM call entirely). After generation,
  Self-RAG checks the answer's faithfulness and relevance, and triggers a
  correction pass if it fails either check.
- **Generation**: Gemini answers strictly from the retrieved context,
  with a constrained prompt that forbids it from using its own general
  knowledge.
- **Evaluation**: a reference question set, RAGAS metrics, and a
  hybrid-vs-naive comparison, so retrieval changes can be measured instead
  of eyeballed.

```
Question
   |
   v
[Multi-Query]   3 reformulations + the original question
   |
   v
[RAG-Fusion]    search children, resolve to parents, fuse via RRF (top 15)
   |
   v
[Re-Ranking]    FlashRank narrows 15 down to top 4
   |
   v
[CRAG]  --off-topic--> immediate fallback answer, no generation call
   | relevant / ambiguous
   v
[Generation]    Gemini answers from context, constrained prompt
   |
   v
[Self-RAG]      checks faithfulness/relevance, corrects if needed
   |
   v
Answer + sources
```

Vector indexes (`chroma_children_*/`, `parent_docstore/`) are generated by
`ingest.py`, not committed to source control.

## Setup

Requires [uv](https://docs.astral.sh/uv/) and a free Gemini API key from
[aistudio.google.com](https://aistudio.google.com/app/apikey). `uv`
manages Python and the virtual environment itself.

```bash
uv sync
cp .env.example .env   # then fill in GOOGLE_API_KEY=AIza...
uv run python ingest.py   # builds the vector index (one-time)
```

## Usage

```bash
uv run python main.py "What is WICKED's purpose?"
```

Each pipeline step is traced in real time, and the output shows the CRAG
verdict, the answer, and the cited sources. A question outside the corpus
(e.g. "What is the capital of France?") gets an explicit fallback answer
instead of a guess.

```bash
uv run streamlit run streamlit_app.py
```

The Streamlit app wraps the same pipeline in a chat interface: toggle any
step (Multi-Query, re-ranking, CRAG, Self-RAG) from the sidebar to compare
naive vs. advanced RAG live, and inspect sources and query reformulations
per answer.

```python
from src.rag import RagPipeline

pipeline = RagPipeline()
result = pipeline.answer("Who is Newt?")
print(result["answer"], result["grounded"], result["sources"])
```

## Run modes

| Mode | LLM | Embeddings | Notes |
|---|---|---|---|
| Gemini API (default) | Gemini 2.5 Flash | Gemini | free-tier quota applies |
| Local LLM | Ollama (mistral, etc.) | Gemini | no LLM quota, embeddings still need an API key |
| Fully offline | Ollama | Ollama (nomic-embed-text) | no quota, no API key at all |
| Docker | Streamlit + Ollama in containers | either | `docker compose up --build` |

Switching embedding provider requires rebuilding the index once
(`uv run python ingest.py --force`), since the index is tied to the
embedding model that produced it.

## Configuration

All parameters live in `src/config.py`: embedding and LLM models, chunk
sizes, RRF and re-ranking parameters, the number of Self-RAG correction
passes, and a `USE_MULTIQUERY` / `USE_RERANK` / `USE_CRAG` / `USE_SELF_RAG`
switch per pipeline step, useful for the evaluation suite and for running
a "naive RAG" baseline.

## Hallucination mitigation

Three complementary layers:

1. **CRAG**: an LLM grades retrieved context as relevant, ambiguous, or
   off-topic before generation runs. Off-topic skips generation entirely.
2. **Constrained prompt**: forbids the LLM from using its own general
   knowledge and forces it to say explicitly when information is missing.
3. **Self-RAG**: after generation, an LLM checks the answer's
   faithfulness to the context and its relevance to the question, and
   triggers a correction pass on failure.

## Status

All core requirements are implemented: French-corpus RAG, hallucination
mitigation, RAG evaluation (RAGAS), a Streamlit app, and a containerized
deployment. Decisions and changes are tracked in
[suivi.md](suivi.md).

|---|---|
| Embeddings | `models/gemini-embedding-001` |

| CRAG / Self-RAG graders | `gemini-2.5-flash` (temperature 0) |
| Re-ranking | `ms-marco-MultiBERT-L-12` (FlashRank, local, multilingual) |
